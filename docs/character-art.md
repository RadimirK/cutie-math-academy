# Генерация внешности персонажей

> Цель — обойтись без художника. Внешность персонажа задаёт LLM, а картинку рисует
> детерминированная программа в едином пиксельном стиле.

## Принцип

**LLM решает, что нарисовать, программа решает, как это рисуется.** Модель никогда не
выдаёт пиксели. Она пишет декларативное описание по строгой схеме, а рендерер превращает его
в пиксель-арт. Так же устроен весь контент проекта: YAML, проверка zod-схемой, CI.

Почему пиксель-арт: в низком разрешении формульность форм незаметна, а большая часть ремесла
(рампы цветов, объём, обводка, блики) сводится к правилам и делается кодом. Вручную задаются
только силуэты деталей.

## Три уровня описания

| Уровень | Где лежит | Кто пишет | Что задаёт |
|---|---|---|---|
| Стиль | `src/art/style.ts` | человек | Размер спрайта, скелет головы, свет, падающие тени, правила рамп. **LLM его не трогает**: на этом держится единый стиль |
| Библиотека деталей | `content/art/parts/<slot>/<id>.yaml` | LLM-автор деталей, человек одобряет | Чёлки, причёски, глаза, рты, одежда, аксессуары в виде форм |
| Внешность персонажа | блок `look:` в `content/characters/<id>.yaml` | LLM-дизайнер | Выбор деталей, их параметры, палитра, эмоции |

### Внешность персонажа

```yaml
look:
  head: 1            # размер головы, 0.9..1.1
  shoulders: 1       # ширина плеч, 0.85..1.15; детали видят её как $shoulders
  palette: { skin: '#f7dccb', hair: '#3d4f8a', eyes: '#4f8fc9', cloth: '#34405f', accent: '#e0b84a' }
  parts:
    hair_back: { part: long_straight, length: 3.8 }
    hair_front: { part: blunt_bangs, length: 0.06, side: 2.6 }
    eyes: { part: soft, shape: half }
    outfit: { part: blazer, neck: ribbon }
    bottom: { part: pleated_skirt, length: 6.3 }
    legwear: { part: stockings }            # top: 6.3 — чулки над коленом
    shoes: { part: loafers }
    accessory: [{ part: round_glasses }]   # в слот можно положить несколько деталей
  emotions:                                # переопределения поверх базовой внешности
    thinking: { eyes: { shape: half, look_x: -1, look_y: -1 }, mouth: { shape: flat } }
    happy: { eyes: { shape: joy }, mouth: { shape: open }, cheeks: { part: blush } }
```

- Слоты `body`, `head` и `mouth` по умолчанию получают детали стиля (`DEFAULT_PARTS`),
  остальные без указания пусты. `part: none` убирает деталь, в том числе в эмоции.
- Эмоция с той же деталью меняет только указанные параметры. Эмоция с другой деталью
  начинает с её значений по умолчанию.
- Эмоция, которой нет в `emotions`, рисуется базовой внешностью. В сценах сейчас
  используются `smile`, `thinking`, `happy`.
- Палитра обязательно содержит `skin`, `hair`, `eyes`, `cloth`. Цвета `cloth2` (рубашка),
  `skirt` (по умолчанию как `cloth`), `legwear`, `shoes`, `accent`, `metal`, `blush`,
  `line` (ресницы) необязательны и выводятся сами.

### Деталь библиотеки

Слот детали — имя папки. Порядок слотов задаёт глубину, от заднего к переднему:
`hair_back, body, legwear, shoes, bottom, outfit, head, cheeks, eyes, brows, mouth, hair_front, accessory`.

```yaml
id: blunt_bangs
desc: Ровная густая чёлка до бровей и длинные пряди по бокам лица.   # каталог для LLM
material: hair          # материал фигур, где он не указан
shade: round            # round — объём со светом слева сверху, flat — только падающие тени, none — как нарисовано
outline: true           # выборочная обводка
seams: true             # каждая фигура — отдельная прядь со своей тенью и швом
highlight: hair_band    # глянцевое кольцо на волосах
params:
  length: { range: [-0.25, 0.15], default: 0.05, desc: докуда чёлка }
  ahoge: { options: [none, curl], default: none }
shapes:
  - strand: { from: [-0.45, -1.0], to: [-0.82, '$length - 0.02'], bend: 0.06, width: [0.34, 0.3] }
    mirror: true
```

**Координаты** считаются в пространстве головы: (0, 0) — центр головы, 1 — её радиус,
y направлен вниз. Фигура стоит в полный рост, около пяти голов:

| y | что там |
|---|---|
| −1.2 | макушка с волосами |
| 0.32 | глаза |
| 1.08 | подбородок |
| 1.5–1.9 | плечи (±1.26 × `$shoulders`) |
| 3.2 | талия (±0.72) |
| 4.0–4.5 | бёдра (±0.94), низ пиджака |
| ≈ 6.7 | колени |
| 9.0–9.3 | щиколотки и подошвы |

Любое число можно заменить выражением над числовыми параметрами: `'$length + 0.1'`
(`+ - * /`, скобки).

**Фигуры:**

| Фигура | Для чего |
|---|---|
| `ellipse: {at, r, rot}` | голова, узлы бантов; с `hollow: true` — контур в пиксель (оправа очков) |
| `poly: [...]` | многоугольник; с `smooth: true` — гладкая кривая через точки |
| `strand: {from, to, bend, width: [корень, кончик]}` | прядь волос: изогнутая, сужается к кончику |
| `stroke: [...]` | линия в один пиксель |
| `stamp: {at, rows, key, shift}` | пиксели как есть, для мелочей: глаза, рты, блики. `key` переводит символ в `материал` или `материал:тон`, `shift` сдвигает на целые пиксели после отражения |

**Позы.** У тела есть параметр `pose` для правой руки: `down` (вдоль тела), `chin` (у
подбородка, задумчиво), `hip` (на поясе). Эмоция меняет позу как любой параметр:
`thinking: { body: { pose: chin } }`.

**Одежда по фигуре.** Тело (`body/basic`) называет свои фигуры: `neck`, `torso`, `arms`,
`hands`, `legs`, `feet`. Одежда рисует простой прямоугольник и обрезает его по нужной
части тела: `clip: arms`, `grow: 1` (на пиксель шире). Поэтому рукава, пиджак и чулки сами
садятся по фигуре при любых параметрах тела, а автору детали не нужно повторять её контур.

**Общие поля фигуры:** `material`, `tone` (фиксированный тон 0–4, без тени и обводки),
`name` (по этому имени к фигуре могут обрезаться другие), `clip` и `grow` (см. выше),
`mirror` (отразить относительно оси лица), `erase` (вырезать из уже нарисованного деталью),
`seam` (отдельный кусок, как прядь при `seams`), `slot` (нарисовать сразу поверх другого слоя,
например хвосты поверх пиджака), `when: {param: value}` (только при этих значениях
параметров-вариантов).

**Материалы:** `skin, hair, eyes, eye_white, cloth, cloth2, accent, line, mouth, blush, metal, shine`.
Цвета берутся из палитры персонажа, поэтому деталь перекрашивается бесплатно.

## Рендерер (`src/art/`)

Чистый TypeScript без DOM: один код работает в браузере и в CI. Одинаковый YAML всегда даёт
одинаковые пиксели.

1. **resolve**: эмоция накладывается на базовую внешность, параметры проверяются.
2. **rasterize**: фигуры превращаются в маски (заливка с 4×4 суперсэмплингом, линии без
   «двойных» углов, штампы как есть).
3. **compose**: детали рисуются сзади вперёд.
4. **volume**: у `shade: round` тень собирается справа снизу, блик ложится слева сверху.
5. **cast**: верхние слои отбрасывают тени (чёлка на лоб, подбородок на шею, `CAST_SHADOWS`).
6. **hair_band**: глянцевое кольцо на волосах.
7. **outline**: край области против пустоты или против того, что сзади, получает самый тёмный
   тон своей рампы. Пряди одной детали получают более мягкий шов.
8. **colors**: из каждого цвета палитры строится рампа на 5 тонов в OKLCH (тени уходят в
   сине-фиолетовый, света в жёлтый).

Рисуется всегда вся фигура на холсте 128×256, а кадр — окно на неё (`FRAMES`): `full` —
весь рост, `bust` — 96×128 (3:4, как карточки коллекции), с запасом над головой. Один рендер на эмоцию, оба кадра режутся из него. `Portrait` рисует бюст в
карточках и полный рост в сценах, лобби и наборе, когда у персонажа нет файла спрайта.
Рендер фигуры занимает около 30 мс.

**Проверки.** Загрузчик контента проверяет схему деталей и внешности, ссылки на детали,
параметры и выражения. `npm run content:validate` рендерит всех персонажей во всех эмоциях.

**Обзорный лист:** `npm run art:render -- <папка> [id ...]` сохраняет `<id>.full.png` и
`<id>.bust.png` (все эмоции в увеличении и в 1×) и отдельные спрайты. Его смотрят люди и
модель-критик.

## LLM-конвейер (этап 2, ещё не сделан)

```
character.yaml (имя, описание, предмет, редкость)
        │
        ▼
  Дизайнер (LLM) ──► look ──► схема + линты ──► рендер ──► обзорный лист
        ▲                                                     │
        └──────────── JSON-патч ◄── Критик (LLM со зрением) ◄──┘   (≤ 3–5 итераций)
                           │
                           │ «не хватает детали: шляпа ведьмы»
                           ▼
                 Автор деталей (LLM) ──► parts/_proposed/ ──► человек одобряет ──► библиотека
```

- **Дизайнер** получает лор персонажа, этот документ, каталог деталей (`id`, `desc`,
  параметры, контактный лист) и лист всего каста, чтобы не повторяться. Отвечает вызовом
  инструмента, JSON Schema которого получается из `LookSchema` через `z.toJSONSchema`.
- **Линты** сверх схемы: контраст волос с кожей и одежды с волосами, несовместимые детали и
  непохожесть на остальной каст (силуэт, палитра, набор деталей). Без последнего модель
  сваливается в среднее.
- **Критик** смотрит на обзорный лист (увеличение nearest-neighbor, иначе модель плохо видит
  пиксели) и проверяет: читается ли персонаж в 1×, различимы ли эмоции, соответствует ли
  описанию, нет ли артефактов. Отвечает «ок» или патчем к `look`.
- **Автор деталей** вызывается, только когда в библиотеке нет нужной детали. Новую деталь он
  проверяет на нескольких тестовых персонажах с разными размерами головы и плеч.

## Известные ограничения

- Позы только у правой руки, ноги всегда вместе. Длина рукава задаётся по вертикали, поэтому
  у поднятой руки короткий рукав ведёт себя неправильно.
- Рука у подбородка плохо читается: кисть сливается с подбородком, а предплечье с пиджаком
  того же цвета.
- Масштаб на экране пока не целочисленный, поэтому пиксели местами разной ширины.
- Привлекательность определяется силуэтами деталей в библиотеке, а не рендерером и не моделью.
